# Member UI checks

The dashboard is the reference for the member interface. `reading-home.css` owns the shared palette and preview components; `responsive.css` owns the app frame, sidebar, header and mobile navigation. `member-components.css` styles controls and navigation cues across all member pages. `member-pages.css` styles page content, and must not redefine the outer shell or theme tokens.

The dashboard retains its editorial grid, open-book artwork and ivory/white split. Other member pages use a continuous ivory background (neutral charcoal in night mode), with the same shell geometry, colour tokens, controls and navigation icons. Night uses neutral #171717 pages and #212121 raised surfaces, white/grey text and restrained gold accents. Dashboard night columns differ in lightness rather than hue. Keep the split scoped to `.reading-home:not(.member-page)` in `responsive.css`. The selected navigation section follows the validated source of a detail page. Breadcrumbs show the current section while the contextual Back link retains the exact source URL.

Member headings use self-hosted Source Serif 4 with optical sizing; DM Sans remains the reading/navigation face. Keep display type regular, use a deliberate size hierarchy, and let book covers carry the catalogue. The reading scale in `member-components.css` uses 16–18px reading text, 17–18px catalogue titles and 48px main actions, including player controls. Desktop covers have more room; all four phone Popular Now books fit one row without a scroll strip. Catalogue books use compact phone rows with 64–72px covers and readable metadata, rather than tall desktop-sized cards. Tablet covers are capped at 150px. Catalogue pagination still limits the number of rendered books per page. Narrow phone heroes stack instead of squeezing text beside the open book. Content panels have restrained corners and dividers, category filters use an underline, and secondary listening search is a text action. Source Serif's unmodified Adobe font and OFL license are stored in `assets/fonts`; there are no runtime third-party font requests.

All header search entry points open the same native dialog. On phones it remains a compact panel with the underlying reading page visible, rather than replacing the screen. The borderless input uses a focus underline and 16-pixel text; the initial state explains what can be searched. Live results have cover art, title, author and availability, plus keyboard selection. Escape/Close restore focus to the invoking button. Enter always submits a normal catalogue query, including during an API failure; choosing a book preserves the source URL for its Back link. Keep the panel height intrinsic when empty and bounded when results scroll.

Preview positions are scoped to account, application path, book and summary revision in browser storage. Speed and volume are shared within that account/application. Edited summaries invalidate old preview positions. Playback works with storage blocked; restoring a position never starts speech automatically. The remembered book cookie contains only a catalogue ID and is scoped to account and app path. Actual recordings retain their existing account-backed position and speed saving.

The PDF reader starts in Fit page, bounded by the viewport while retaining Fit width and explicit zoom levels. A single Previous / page-number input / Next row sits below the PDF. Routine page announcements remain available to screen readers without duplicating visible text above the book; loading, errors and action confirmations remain visible. Turning a page resets the PDF scroll position and brings its start into view. Zoomed pages use normal scroll chaining so the surrounding document can continue scrolling at a PDF boundary. Progress/bookmarks use the existing account-backed API.

The catalogue's All books link sits outside the horizontally scrolling category list, so selecting even a distant category cannot hide it. Category links retain `view=all`, sorting, search and availability. All books clears the category within the catalogue; Clear filters resets the catalogue instead of returning to the dashboard. The All books heading stays stable, with category context in the selected filter and result count.

## Automated checks

- `php tests/navigation_test.php` checks safe returns and navigation-section context.
- `node tests/listening_preferences_test.mjs` checks saved position/settings, stale summaries, account/application isolation, bounded history and storage failures.
- GitHub Actions' **Member UI consistency** job uses an isolated SQLite library and Chromium at 1440, 1280 and 390 pixels in both themes. It compares member-shell geometry and palette with the dashboard, checks the enlarged sidebar/header dimensions, and compares header/navigation pixels after neutralizing active indicators, dynamic reminder counts and the intentional dashboard-only background split. The actual split is asserted separately: only desktop/laptop home pages may have it. Reading text, catalogue titles, cover widths and main action sizes have minimum-size assertions. It also checks preview continuation, remembers the selected book and rejects overflow/browser errors. Each size/theme checks compact search, live/empty results, clearing, Escape/focus restoration, keyboard selection and contextual Back navigation. A separate 320-pixel phone test checks panel fit and ordinary form submission after live-search failure.
- Navigation comparisons ignore per-channel rasterization differences up to 8/255 and permit at most 0.25% changed pixels; geometry and palette comparisons remain exact. Selected icon styling is tested separately. Every UI run retains full-page screenshots and an HTML report as the `member-ui-visual-review` artifact for seven days. These include dashboard, catalogue, book details, loans, favorites, profile and messages. Page content is reviewed through these screenshots; the automated pixel comparison covers the shared shell rather than a frozen full-page content baseline.
- Night checks also require neutral RGB channels on the page, raised/inset surfaces and borders, and at least 4.5:1 contrast for main, secondary and gold text on raised surfaces. A real profile-theme switch checks immediate appearance, browser theme colour, persistence across navigation and return to the original day palette.
- Reader UI tests use an original three-page PDF in the isolated UI library, never a real uploaded book. They exercise both page controls, fit-page bounds, zoomed scroll handoff, responsive geometry and saved-page restoration. The fixture refuses databases outside `tests/runtime`, uses a random owned filename and restores/removes only that fixture afterward.

For local CI-style execution, install the development dependencies with `npm ci`, install Chromium with `npx playwright install chromium`, create a disposable database under `tests/runtime` using `tests/make_sqlite.php`, and set `BOOKTRACK_SQLITE` to its absolute path before `npm run test:ui`. The runner refuses external hosts and databases outside `tests/runtime`, and starts its own server on port 8115. Normal PHP/Apache hosting does not require Node or Playwright.

The screenshot checks follow [Playwright's visual-comparison guidance](https://playwright.dev/docs/test-snapshots). Keep the browser/runtime environment consistent when comparing review images.
